# Базовые правила проекта

> Соглашения предварительно определены по текущим файлам. Уточняйте этот документ, когда структура проекта изменится.

## Именование

- **Файлы:** локальные вспомогательные скрипты имеют описательные имена в kebab-case; существующие имена и экспортированные Webflow-файлы разнородны.
- **Переменные и функции:** для нового кода используйте camelCase.
- **CSS-классы:** существующая разметка использует классы Webflow с дефисами и подчёркиваниями. Не переименовывайте их без изменения соответствующей разметки и стилей.
- **Классы JavaScript:** пользовательские классы в просмотренных локальных скриптах не обнаружены.

## Структура модулей

- Проект представляет одну статическую страницу; HTML разложен по `src/components/` и `src/sections/`, CSS хранится в `src/styles/`, браузерные скрипты — в `src/scripts/`.
- Корневой `index.html` определяет состав страницы директивами `@include`; `scripts/build-site.mjs` собирает результат в `dist/`.
- `src/scripts/features/content-interactions.js` управляет FAQ и вкладками истории; `src/scripts/features/mobile-menu.js` управляет мобильным меню.
- Текст и секции должны быть видны без JavaScript и без внешних анимационных библиотек. Не добавляйте скрытые стартовые состояния, полноэкранные прелоадеры или scroll-reveal, которые могут оставить содержимое недоступным.
- Редактируйте исходники в `src/`; не правьте вручную сгенерированные файлы в `dist/`.
- Используйте существующие атрибуты data-* и классы при работе с DOM.

## Обработка ошибок

- Проверяйте наличие DOM-элементов и браузерных API до обращения к ним; в скриптах используются ранние возвраты.
- Хранилище сессии обёрнуто в try/catch; сетевые и медиа-операции обрабатываются локально, когда это необходимо.
- Не вводите общий механизм ошибок, пока у сайта нет соответствующего прикладного слоя.

## Управление потоком

- Поддерживайте прямой, читаемый поток выполнения. Обрабатывайте отсутствующие элементы и неприменимые случаи ранним return.
- Избегайте глубокой вложенности и разделяйте независимые взаимодействия на небольшие именованные функции.

## Логирование

- Устойчивый формат логирования в локальных скриптах не обнаружен. Не оставляйте отладочные сообщения console в рабочем коде.

Браузерные проверки запускаются через Playwright и находятся в `tests/e2e/`.
