## Архитектура и решения
- Страница и визуальная логика сохраняются, исходная структура теперь разделена: index.html подключает части из src/components/ и src/sections/; CSS лежит в src/styles/; браузерные сценарии — в src/scripts/.
- Для hero используется один согласованный режим: sticky-сцена .hero-prize-transition, которую создаёт hero-prize-transition.js. Удаляются только конфликтующие старые CSS-переопределения, которые задают для того же hero обычный поток и затем снова включают sticky-переход.
- Локальная схема слоёв фиксируется в одном месте: фото ниже содержимого hero; заголовок, даты и организаторы выше фото; секция призов начинает перекрывать hero только по текущему scroll progress и не затрагивает заголовок в начальном состоянии.
- Контент по умолчанию видим. app.js включает текстовые reveal-анимации только после успешной настройки триггеров; fallback снимает оставшееся скрытие при отсутствии зависимостей или ошибке. Поведение проверяется с загруженными стилями и заблокированными удалёнными скриптами.
- Локальные runtime-ресурсы находятся в src/assets/images/ и src/assets/fonts/ и копируются сборкой в dist/assets/. Ссылки проходят аудит перед выпуском.
- Playwright и Node HTTP-сервер используются только в разработке. Скриншоты, отчёты тестов, browser profiles и graphify cache хранятся в исключённых из Git местах. Общее правило *.png в .gitignore не добавляется.
- Режим логирования verbose относится к диагностике реализации и тестов. В production-коде нет постоянного scroll-спама; fallback пишет одну диагностическую запись с кодом причины, без текста пользователя и содержимого формы.
- Документация обновлена под текущую структуру frontend. Целевые серверные слои в .ai-factory/ARCHITECTURE.md сохранены; backend отсутствует.
